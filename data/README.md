# Data layout

Real data are **not** distributed (see `docs/data_availability.md`). To reproduce, place processed
inputs as follows (or override roots in `configs/default.yaml` / `.env`):

```
data/processed/holstein/parse_qc/
    holstein_genotype_matrix_qc.npy      # (1092, 164312) dosage 0/1/2, no missing
    holstein_phenotype_table.csv         # fixed-effect-adjusted phenotypes; trait milk_le_sum_305
    holstein_snp_metadata.csv            # chromosome, position (Btau_4.6.1 source; see A6 audit)
    holstein_sample_alignment.csv        # sample_id, order
data/processed/holstein/relationship_splits/
    holstein_grm.npy                     # VanRaden GRM (1092, 1092)
splits/holstein/{random,relationship_group,leave_cluster_out}/   # generated by build_holstein_splits.py
```

- `data/public/` -- any public-accession data used (list accessions here if applicable).
- `data/processed_placeholder/` -- optional small synthetic mock inputs to test the pipeline.
- `data/private_not_uploaded/` -- restricted data the user holds locally; never committed.

Field descriptions and access terms are in `docs/data_availability.md`.

## Holstein phenotype provenance (important)
The Holstein phenotypes were available only as **pre-adjusted records**; the exact fixed-effect
correction model (and whether it was applied by the data provider or upstream) is **not
recoverable** from the supplied files. They are treated as the dataset-defined response. No raw
records or fixed-effect covariates are included, and no fixed-effect re-estimation is performed in
this pipeline — so there is no fold-level phenotype-adjustment leakage, but the provider-side
correction model is an acknowledged dataset-provenance limitation.
